## Images & Icons

### Benefits
- **Identification** - images are easy to recognize
- **Expression** - breadth of artistic expression that can make design more engaging and enjoyable

### Types of Iconic Representation
- **Similar** - visually analogous to action, object, concept (e.g., right turn sign, falling rocks sign)
- **Example** - things that exemplify or are commonly associated (e.g., airplane for airport, scissors for cut)
- **Symbolic** - represent concept at higher level of abstraction (e.g., lightning bolt for electricity, droplet for water)
- **Arbitrary** - little or no relationship to concept, must be learned through standard (e.g., radioactive symbol, biohazard)

### Use of Abstraction
- Simplifying highly concrete, realistic representations makes them easier to interpret, up to the point where further abstraction obscures the icon's semantics
- Abstraction makes icons more generic, more canonical, less complex
- Example: calculator icon progressively simplified from realistic to abstract (at some point it stops being recognizable)

### Principles of Icon Design
1. **Immediacy** - can be perceived effortlessly and involuntarily by being bold, clear, balanced
2. **Generality** - represents a class of items rather than an individual element, by removing details that may vary (e.g., bathroom icons strip away individual features)
3. **Cohesiveness** - set of icons that function together by sharing visual variables (consistent style across an icon set)
4. **Characterization** - call to mind one or more distinctive features (e.g., a hanger for a closet, a distinctive silhouette)

## Design Languages

- Many choices about visual variables and syntax of composition across a web app
  - Problem: how do you ensure choices are made consistently?
- **Solution: Design Language**
  - Describes how to express ideas and concepts in the interface
  - May be communicated through Human Interface Guideline documentation
  - Example of consistency and standards (Nielsen's heuristic)

### Design Language Components

#### Elements
- The individual visual building blocks: view controls, source indicators, detail displays, fluff/branding, action buttons
- Example: Google 2004 had elements like navigation links, search boxes, result counts, sponsored links, action buttons

#### Syntax
- How elements are composed into larger structures
- Common syntax patterns: **task** (form/input areas), **placeholder** (loading states), **toolbar** (navigation bars), **list** (repeated items like email inboxes)

### Evolution Example: Google 2004 vs. 2016
- Google 2004: text-heavy, minimal visual hierarchy, functional but visually sparse
- Google 2016 (Material Design): cards with shadows, clear visual hierarchy, consistent icon set, toggle switches, navigation drawers with icons

### Common Layout Patterns
- **Header with text blocks** - top nav bar, large header, large text block below
  - Very common pattern across many websites
- Heatmap studies show consistent placement patterns across the web for elements like: banner, breadcrumb, comments, copyright, featured content, footer, header, hero, login, logo, menu, nav, search, sidebar, sitemap, social/Twitter links
  - These conventions create user expectations (users expect to find nav at top, logo top-left, search top-right, etc.)

### Why It Matters
- **Idioms** - users will have idioms they expect to see, particularly if suggested by other related elements on the page
- **Branding** - users will see your website and have particular associations based on what it exemplifies (e.g., a photography site that looks like ESPN sends mixed signals)

### Goals in Designing a Design Language
- Offer guidance and options on:
  - **Colors:** examples of color palettes
  - **Typography:** justification, sizes, fonts, different heading levels
  - **Organization**
- Support different resolutions and devices
- Support universal design (visually impaired, color blind users)
